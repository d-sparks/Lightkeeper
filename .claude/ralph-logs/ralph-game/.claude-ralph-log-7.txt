Done. Here's what was implemented across 3 files:

**Problem**: The TRACK button on the "Lost Supplies" side quest sent a `TRACK_QUEST` message to the server and updated the tracked flag, but the guide arrow/minimap dot never changed because the `find_manifest` step had no `objective` field. The system fell back to the main quest's objective.

**Solution** (3 changes):

1. **`content/quests/lost_supplies.json`** — Added `objective` (static fallback pointing to the quarantine wing entrance at `outpost_workshop`) and `objectiveItem: "supply_manifest"` to the `find_manifest` step.

2. **`server/scripting/quest-tracker.js`** — Updated `getActiveObjective()` to recognize steps with `objectiveItem` (even without a static `objective`) and pass the `objectiveItem` field through in the returned objective data.

3. **`server/game-loop.js`** — Added `_findItemInRooms(itemType)` method that scans active rooms for a ground item by type. Updated `_sendQuestObjective()` to resolve `objectiveItem` to the item's actual location when the room has been generated, falling back to the static objective otherwise.

**How it works**: When you track the "Lost Supplies" quest, the arrow points to the quarantine wing entrance. Once the quarantine wing is generated (someone enters it), the arrow dynamically resolves to where the `supply_manifest` actually spawned in the procedural room.
